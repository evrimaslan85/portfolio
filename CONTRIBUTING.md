# Contributing

Start with the [current product documentation](docs/index.md), [roadmap](docs/roadmap.md), [decisions](docs/decisions.md), and [license scope](docs/business/licensing.md). This repository ships early-release packages alongside future plans; label implemented behavior and proposals accurately.

Keep a change focused. Update relevant documentation and fictional fixtures with contract/behavior changes. Run `npm test` on Node.js 22+. For UI changes, open the preview, check keyboard/mobile behavior, and confirm both forms still show the same content.

Use original or appropriately licensed public material. Do not copy private source, client screenshots, production configuration, external business records, or personal data into a contribution. Preserve third-party notices and document dependency licenses. Contributions use the license applying to their package; see the licensing policy. No copyright assignment is requested.

Do not put GPL-only runtime code into the MIT standalone package without the necessary rights. The public schema may be shared; separate implementations should stay separate.

For proposed product work, state the user problem, expected behavior, scope, acceptance criteria, and privacy/compatibility implications. Avoid promising support, paid terms, or release dates without an owner decision.
